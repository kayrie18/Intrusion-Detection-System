Watching network traffic for attacks with Suricata

This project installs and configures Suricata, an open-source intrusion detection system (IDS), to inspect traffic on my own network and raise an alert whenever a packet matches a known attack pattern. A real alert from my test run:

11/09/2026-01:30:34.312702  [**] [1:1000006:1] LOCAL SQL injection attempt (UNION SELECT) [**] [Classification: (null)] [Priority: 3] {TCP} 192.168.214.57:46744 -> 192.168.214.55:8080

What the system does

  • Runs Suricata 8.0.8 on Windows 11 with the Npcap capture driver, listening on the Wi-Fi adapter.
  • Uses six custom rules for ping, port scans, SSH brute force, scanner user-agents, directory traversal and SQL injection.
  • Writes alerts to fast.log and detailed JSON to eve.json.

Lab layout

Phone (hotspot, 192.168.214.57)  -->  Laptop Wi-Fi adapter (192.168.214.55)  -->  Npcap + Suricata  -->  fast.log

All testing was done on my own devices, as the project guidelines require. I first tried WSL2, but WSL would not install on my laptop, so I ran Suricata directly on Windows.
